# 앰플랩 업무 대시보드

대표님 포함 세 사람이 하루에 5~7개 직무를 오가는 스타트업을 전제로 만든 통합 대시보드.
이메일·디스코드로 흩어져 들어오는 할일을 AI가 뽑아 **직무별로 분류·우선순위화**하고,
Gmail에는 라벨을 되돌려 붙이고, 잡은 시간은 구글 캘린더와 **양방향**으로 맞춘다.
세 사람이 같은 화면을 동시에 써도 겹치거나 덮어쓰지 않도록 만들어져 있다.

## 실행

```bash
npm install
cp .env.example .env.local   # 키를 채우면 실제 추출·연동. 없어도 데모로 돈다
npm run dev                  # http://localhost:3000
```

## 화면 구성 (2026-09 리디자인)

| 화면 | 답하는 질문 |
|---|---|
| **대시보드** | 오늘 뭐부터 하나. 지표 4개 · 최근 7일 인입/완료 · 지금 할 일 · 팀 현황 · 오늘 일정 · 최근 활동 |
| **새로 들어온 것** | 뭐가 들어왔고 분류가 맞나. 붙여넣기 추출 + 직무별 칸반 |
| **일정** | 언제 하나. 주/월 달력, 끌어다 놓기, 구글 캘린더의 다른 일정이 점선으로 깔림 |
| **진행 상황** | 왜 아직 안 끝났나. 기한 순 목록 + 단계 흐름 |
| **메일함** | 무슨 메일이 어느 직무로 분류됐고 무슨 할일이 나왔나 |
| **설정** | 구글 연결 · AI · 팀 명단 · 키워드 규칙 · 접근코드 |

## 구글 연동 (Gmail 라벨링 + 캘린더 양방향)

계정은 **하나**(대표님)를 연결하고 세 사람이 함께 본다.

1. Google Cloud 콘솔 → 프로젝트 → **Gmail API**, **Google Calendar API** 사용 설정
2. OAuth 동의 화면(외부, 테스트 사용자에 대표님 계정) → **OAuth 클라이언트 ID(웹)** 생성
3. 승인된 리디렉션 URI: `https://<도메인>/api/google/callback` (설정 화면에 정확한 값이 표시된다)
4. Vercel 환경변수 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GEMINI_API_KEY`, `APP_PASSCODE` 추가 → 재배포
5. 대시보드 → 설정 → **구글 계정 연결** → 대표님 계정으로 동의
6. 메일함 → **지금 동기화**

### 메일이 지나는 길

```
Gmail (설정의 검색 조건, 기본 최근 7일)
  → 키워드 규칙 (설정에서 편집. "이 단어면 무조건 이 라벨")
  → Gemini: 라벨(직무 1~2개 또는 참고) · 한 줄 요약 · 할일 추출
  → 대시보드 저장 (중복은 표시만)
  → Gmail에 "업무/CS" 같은 라벨을 실제로 붙임  ← 대시보드가 죽어도 메일함에서 필터가 된다
```

- 규칙이 "참고"라고 하면 AI가 뭐라 해도 할일을 만들지 않는다 (뉴스레터에서 할일이 나오면 그게 오류다).
- Gemini 호출이 실패한 메일은 처리 표시를 거두고 다음 실행에서 다시 읽는다. 추측 라벨을 붙이고 넘어가지 않는다.
- 화면이 열려 있으면 5분마다 자동, 버튼은 즉시. 크론은 하루 한 번(무료 플랜).
- 사람이 라벨을 고치면 Gmail 라벨도 같이 바뀐다.

### 캘린더가 맞춰지는 규칙

- 대시보드에서 시간을 잡으면 이벤트 생성, 옮기면 수정, 비우면 삭제.
- 캘린더에서 옮기거나 지우면 syncToken으로 받아 slot에 반영 (화면이 열려 있으면 1분, 크론 하루 1회).
- 우리가 만든 이벤트에만 `opsTaskId`가 숨어 있어 남의 회의를 할일로 바꾸지 않는다.
- 주 달력에 **다른 일정이 점선 상자로** 깔려 겹치게 잡는 실수를 막는다.
- 진실은 "마지막에 손댄 쪽". 붙여넣기로 뽑은(저장소에 없는) 할일은 캘린더에 올라가지 않는다.

## 디스코드 (채널 ID를 손으로 넣지 않습니다)

환경변수는 `DISCORD_BOT_TOKEN` **하나뿐**입니다. 봇이 서버에 들어가 있으면 채널 목록은
봇이 스스로 알기 때문에, 사람이 개발자 모드를 켜고 ID를 복사해 붙여넣고 재배포할 이유가 없습니다.
설정 → 디스코드 → **서버 불러오기** 를 누르면 채널이 카테고리별로 뜨고 이름으로 고릅니다.

### 두 갈래로 들어옵니다

**① 자동 수집** — 채널·스레드의 새 대화를 덩어리로 읽어 AI가 할일을 판단합니다.

| 모드 | 뜻 |
|---|---|
| **모든 채널** (기본) | 봇이 읽을 수 있는 채널 전부. **새 채널이 생겨도 아무것도 안 해도 잡힙니다.** 잡담 채널만 체크를 풀면 됩니다 |
| 고른 채널만 | 체크한 채널만 봅니다 |
| 자동 수집 끔 | 📌로 콕 집은 것만 받습니다 |

기본을 "모든 채널"로 둔 이유: 앰플랩 서버는 채널이 프로젝트·고객사 단위(`ai-os`, `판틀110`)라
거의 전부가 업무 대화입니다. 고르게 만들면 새 프로젝트 채널이 생길 때마다 누군가 설정을 열어야 하는데,
그 한 번을 잊으면 그 채널의 할일이 통째로 사라집니다. **빼는 쪽이 훨씬 드뭅니다.**

**② 📌 반응으로 콕 집기** — 메시지에 📌를 붙이면 AI 판단과 무관하게 할일이 됩니다.

- 사람이 확정한 것이라 **오탐이 0**입니다
- **이미 지나간 메시지에도** 붙일 수 있습니다 (자동 수집은 커서 뒤로 지나간 대화를 못 잡습니다)
- 대시보드를 열지 않고 **디스코드 안에서** 할일을 등록하는 유일한 길입니다
- 앞선 대화 4개를 맥락으로 함께 읽습니다 — "그거 처리 부탁"만으로는 할일이 안 되기 때문입니다
- 이모지는 설정에서 바꿀 수 있고(📌 ✅ 📝 🔥 ⭐), 끌 수도 있습니다

같은 건이 양쪽으로 들어오면 중복으로 **표시만** 합니다 (합치지 않는 이유는 CLAUDE.md 설계 결정 2번).

### 봇 준비

1. 디스코드 개발자 포털에서 앱·봇 생성 → 토큰 발급
2. 봇 설정에서 **Message Content Intent를 켭니다** (안 켜면 본문이 빈 채로 옵니다)
3. 서버에 초대 — `채널 보기` · `메시지 기록 읽기` · `메시지 보내기` 권한
4. Vercel 환경변수 `DISCORD_BOT_TOKEN` → 재배포
5. 설정 → 디스코드 → 서버 불러오기 → **지금 수집**

봇이 못 읽는 채널(초대 안 된 비공개 채널 등)은 한 번 시도한 뒤 **일주일간 건너뜁니다.**
매 실행마다 같은 403을 채널 수만큼 받지 않기 위해서입니다. 권한을 고쳤으면 목록을 새로고침하세요.

**수집 주기.** 화면이 열려 있으면 5분마다, 크론은 하루 한 번(무료 플랜). 새 대화가 없으면
AI를 부르지 않으므로 비용은 실제로 대화가 오갈 때만 듭니다.

## 돈 (얼마나 드는가)

**디스코드 봇은 무료입니다.** 개발자 포털도, 봇도, API도 요금이 없습니다. 상시 서버도 필요
없습니다 — 대시보드가 주기적으로 읽어가는 폴링 방식이라서요. Vercel Hobby와 Upstash도 무료 등급이 있습니다.

돈이 드는 건 **AI 호출뿐**입니다. 그래서 상한을 코드에 걸어 두었습니다.

### 0원으로 돌리려면

1. `GEMINI_API_KEY`만 넣고 `ANTHROPIC_API_KEY`는 비웁니다 (Claude는 무료 등급이 없습니다).
   Gemini는 Flash·Flash-Lite에 무료 등급이 있습니다.
2. 설정 → **AI 사용량과 상한**에서 하루 상한을 무료 등급 한도 아래로 잡습니다.
   (정확한 한도는 [AI Studio의 Rate limit 화면](https://aistudio.google.com/rate-limit)에서 확인)
3. 더 아끼려면 디스코드를 **&quot;자동 수집 끔 + 📌&quot;** 로 두세요. 누가 반응을 붙일 때만 AI가 돕니다.

**무료 등급의 대가는 데이터입니다.** 구글 약관상 무료 등급은 보낸 내용과 응답을 제품 개선에
쓸 수 있고 사람이 검토할 수도 있습니다. 유료 등급은 그러지 않습니다. 고객 메일과 사내 대화를
넣는 도구이므로 이건 알고 정해야 하는 문제입니다.

### 상한에 닿으면

자동 수집이 멈추고 **다음 날 이어서 읽습니다.** 커서를 옮기지 않고 처리 표시도 남기지 않으므로
원문이 그대로 남아 있습니다 — 사라지는 할일은 없고 미뤄질 뿐입니다.
📌로 콕 집은 것과 직접 붙여넣기는 상한 밖입니다(사람이 지금 확정한 것을 막으면 그건 고장입니다).

### 호출을 줄이는 장치들

| 장치 | 효과 |
|---|---|
| 새 대화가 없으면 AI를 부르지 않음 | 조용한 날은 0회 |
| 한 채널에 **3건 이상 쌓여야** 호출 | 한 줄씩 올라올 때마다 부르지 않음. 한 대화 6회 → 1~2회 |
| 자동 수집 간격 (기본 10분, 설정 가능) | 길게 둘수록 비례해서 줄어듦 |
| 메일은 한 번에 최대 20통 | 첫 실행에서 수백 통을 한꺼번에 처리하지 않음 |
| 키워드 규칙의 &quot;참고&quot; 라벨 | 뉴스레터는 걸러져 할일 추출을 타지 않음 |

설정 화면에 **오늘 몇 번 썼는지**가 수집·콕집기·붙여넣기로 나뉘어 표시되고,
상한의 80%를 넘으면 상단에 칩이 뜹니다.

## 세 사람이 함께 쓸 때

- **접근코드**(`APP_PASSCODE`) 하나로 문을 잠그고, 사이드바에서 **내 이름**을 고른다. 이름은 이력에 남는다.
- 할일마다 **version**이 있어 두 사람이 같은 카드를 동시에 고치면 나중 저장이 거절(409)되고
  "OO님이 방금 바꿨습니다"와 함께 최신 값으로 갈아끼운다. 조용히 덮어쓰지 않는다.
- **최근 활동**에 누가 무엇을 바꿨는지 남는다 (담당·상태·시간·라벨·설정).
- 30초마다 전원이 같은 데이터를 다시 받는다. 세 사람이 다른 숫자를 보는 시간이 30초를 넘지 않는다.
- 팀 명단·키워드 규칙·메일 조건은 **설정 화면**에서 고치고, 저장 즉시 모두에게 적용된다. 재배포가 필요 없다.

## 핵심 플로우

1. 왼쪽 패널에 원문을 붙여넣거나 샘플 버튼으로 주입
2. **AI로 할일 추출하기** → `/api/extract` → Claude(`claude-sonnet-5`)가 JSON 배열 반환
3. 오른쪽에 할일 카드 (제목 / 직무 / 우선순위 / 마감 / 담당자 / 근거 한 줄)
4. 카드 클릭 → 왼쪽 원문에서 그 근거 문장이 노란색으로 하이라이트
5. 카드 위에서 **우선순위·담당자를 사람이 직접 바꾼다**
6. 아래 직무별 칸반에서 카드를 끌어 상태 변경. **다른 직무 레인에 놓으면 직무도 함께 바뀐다**

## 두 개의 화면

같은 데이터를 서로 다른 질문에 답하도록 두 번 그린다.

| 탭 | 답하는 질문 | 형태 |
|---|---|---|
| **오늘** | 뭐부터 해야 하나 | 마감이 가까운 순. D-Day / D-1 / 이번 주 / 그 이후 / 미정 |
| **인입** | 새로 뭐가 들어왔고 분류가 맞나 | 원문 입력 + 직무별 칸반 |

`오늘`은 완료해도 항목을 목록에서 빼지 않고 제자리에 취소선으로 남긴다.
체크하는 순간 사라지면 연속으로 처리할 때 위치가 계속 바뀌어 헷갈리고,
"오늘 무엇을 했는지"도 화면에서 사라진다.

일정(미팅·외부 약속)은 다루지 않는다. 캘린더가 이미 하고 있고,
이 프로토타입이 맡은 것은 마감이 있는 할일 쪽이다.

## 아침 요약

대시보드는 열어야 보이지만 누락은 "안 열어서" 생긴다. 그래서 처리 관문은
화면이 아니라 알림이 맡는다. 매일 아침 디스코드로 마감이 임박한 할일을 밀어준다.

- 기한 지남 / 오늘 마감 / 내일 / 이번 주만 넣는다. 먼 것까지 매일 나열하면
  읽지 않게 되고, 그러면 알림이 있으나 마나가 된다.
- 디스코드 메시지 상한(2000자)을 넘으면 항목을 자르되 빠진 건수를 밝힌다.
  본문과 꼬리를 따로 만들어, 링크와 집계처럼 항상 남아야 할 줄은 지킨다.
- 보낼 채널은 `DISCORD_DIGEST_CHANNEL`. 없으면 `DISCORD_CHANNELS`의 첫 채널을 쓴다.
- **봇에 그 채널의 메시지 보내기 권한이 필요하다.** 수집만 할 때는 읽기 권한만
  있으면 되지만 요약은 보내야 한다.

화면 상단 `연동 상태`의 **아침 요약 보기**로 지금 나갈 내용을 확인할 수 있고,
거기서 바로 보낼 수도 있다. 크론은 매일 09:00 KST에 돈다(수집은 08:50).

## 담당자 추천

앰플랩은 "이관이 가능한 유형이 확인되면 위임하고, 이후 유사한 건은 같은 사람에게
이어지도록" 운영한다. 그 패턴을 그대로 옮겼다.

담당자가 비어 있는 할일마다 과거 이력을 보고 한 명을 제안한다. 근거는 두 가지다.

| 근거 | 조건 | 표시 |
|---|---|---|
| 유사 업무 | 같은 직무 안에서 제목 유사도 0.3 이상 | "비슷한 개발 업무 2건을 박서연이 맡았습니다" |
| 직무 이력 | 같은 직무 2건 이상, 한 사람이 과반 | "지원사업 업무 3건 중 2건을 이수민이 맡았습니다" |

**유사 업무 판정을 같은 직무 안으로 한정한 이유.** 직무를 넘어 비교하면 고객사
이름 하나로 전혀 다른 일이 묶인다 — "다온컴퍼니 녹음 오류 재현"(개발)과
"다온컴퍼니 플랜 증설 제안"(Sales)이 그 예다. 이관은 직무 안에서 일어난다.

**자동 배정하지 않고 제안만 한다.** 위임은 사람이 정하는 일이고, 근거를 함께
보여줘야 그 판단이 가능하다. 근거가 된 과거 할일 제목을 같이 띄운다.

제안은 저장하지 않고 화면에서 매번 다시 계산한다. 한 건을 지정하는 순간
비슷한 다른 건에도 근거가 생겨야 하는데, 수집 시점에 굳혀두면 반영되지 않는다.

## AI가 정한 값을 사람이 덮어쓰는 경로

이 프로토타입의 전제는 "AI 분류를 100% 믿지 않아도 된다"이다.
추출된 네 가지 값 모두 사람이 고칠 수 있어야 그 전제가 성립한다.

| 값 | 사람이 고치는 방법 |
|---|---|
| 직무 | 칸반에서 다른 직무 레인으로 드래그 |
| 상태 | 칸반에서 다른 컬럼으로 드래그 |
| 우선순위 | 카드의 우선순위 배지 (드롭다운) |
| 담당자 | 카드의 담당자 배지 (드롭다운, 명단은 `lib/team.ts`) |

담당자가 `미지정`인 카드는 배지가 주황색으로 뜨고, 상단 요약에
**담당자 미지정** 건수가 집계된다. 3인 팀에서 "이건 누가 하나"가
비어 있는 것 자체가 처리해야 할 신호이기 때문이다.

원문에서 유추한 이름이 팀 명단에 없는 경우(예: 고객사 담당자)에도
그 값이 선택지에서 사라지지 않는다.

추출 결과는 누적된다. 세 샘플을 차례로 넣으면 여러 채널의 할일이 한 보드에 모인다.

## 데모 모드

`ANTHROPIC_API_KEY`가 없거나 API 호출이 실패하면 **500을 내지 않고** 미리 정의한
결과로 폴백하고 화면 상단에 `데모 모드` 뱃지를 띄운다. 뱃지에 마우스를 올리면
폴백 사유가 보인다. 시연 중 빈 화면이 나오지 않는 것이 이 프로토타입의 요구사항이다.

- 샘플 3종 → 각각에 대응하는 프리셋 결과 (`lib/samples.ts`)
- 임의의 텍스트 → 원문 기반 최소 추출기 (`lib/demo.ts`). 정확도가 아니라
  "무언가는 반드시 나온다"가 목적

프리셋 마감일은 절대 날짜로 굳혀두지 않았다. 원문의 "이번 주 금요일", "다음 주 초"와
결과가 항상 맞도록 시연 당일 기준으로 계산한다(`PresetDue`). 언제 열어도 날짜가 어긋나지 않는다.

## 중복 처리

디스코드 샘플의 "다온컴퍼니 녹음 잘림" 건은 CS 메일 건과 같은 일이다.
같은 일이 여러 채널로 중복 인입되는 것이 이 문제의 핵심이라 **자동 병합하지 않고
`중복 의심` 뱃지만 붙여** 사람이 판단하게 둔다.

비교는 글자 2-gram 포함도(`lib/dedupe.ts`)로 한다. 한국어는 조사·어미가 흔들려서
("재현하기" vs "재현하고") 단어 단위 비교가 잘 깨진다. 실제 프리셋에서 의도한
중복 쌍은 0.57, 나머지 모든 쌍은 0.13 이하로 임계값 0.5와 간격이 넉넉하다.

## 구조

```
app/
  page.tsx              유일한 상태 소유자 (로컬 state, DB 없음)
  api/extract/route.ts  Anthropic 호출 + 데모 폴백
lib/
  types.ts    도메인 타입 (직무 9종 / 우선순위 / 상태)
  roles.ts    직무별 배지 색 — Tailwind JIT 때문에 클래스 문자열을 정적으로 보관
  dates.ts    KST 기준 오늘, 상대 요일 계산
  samples.ts  샘플 원문 3종 + 데모 프리셋
  prompt.ts   시스템/유저 프롬프트 (오늘 날짜 주입)
  parse.ts    모델 출력 방어적 파싱 (코드펜스·잡텍스트·표기 흔들림 흡수)
  dedupe.ts   중복 판정
  demo.ts     임의 텍스트용 최소 추출기
  team.ts     3인 팀 명단 (담당자 드롭다운 선택지)

  SourcePanel / TaskList / TaskCard / SummaryStrip / KanbanBoard

```

드래그는 라이브러리 없이 HTML5 `draggable`을 쓴다. 시연에서 의존성을 하나라도 줄이려는 선택.

## 프롬프트에서 신경 쓴 것

- JSON 배열 외 출력 금지 (설명·마크다운 코드펜스 금지)
- 상대 날짜를 **오늘 날짜를 주입해** 실제 `YYYY-MM-DD`로 변환시킴
- `source`는 원문 문장을 글자 그대로 복사하도록 강제 — 하이라이트가 여기에 걸리고,
  근거를 지어내지 못하게 하는 장치이기도 하다
- 상황 공유·인사말은 할일이 아니라고 명시

모델이 규칙을 어겨도 `lib/parse.ts`가 흡수하고, 그마저 실패하면 데모 모드로 떨어진다.

## 검증한 것

- `npm run build` 통과
- 샘플 3종 추출 → 카드 10개, 중복 1건 표시, 요약 스트립 집계 일치
- **10개 카드 전부** 클릭 시 원문에서 근거 문장 하이라이트 성공
- 드래그로 상태 변경 / 다른 직무 레인 이동 시 직무 변경 동작
- 우선순위·담당자 드롭다운 변경이 카드·칸반·요약 집계에 모두 반영
- 드롭다운을 조작해도 카드 선택(하이라이트)이 오작동하지 않음
- 팀 명단에 없는 담당자 이름도 선택지에 유지
- 임의 텍스트 데모 폴백: 상대 날짜("내일", "이번 주 금요일") 변환과 직무 추정 동작,
  할일 아닌 문장은 제외
- 파서: 코드펜스, 앞뒤 설명, 문자열 안 대괄호, 표기 흔들림, JSON 아닌 응답 처리
- 빈 본문 / 잘못된 JSON 요청 → 400
- 768 / 930 / 1440px 폭에서 가로 스크롤 없음

자동 연동 관련:

- 메일 웹훅 — JSON / form-urlencoded / multipart 세 형식 모두 수신 확인
- 인증 — 비밀 없음·틀린 비밀 모두 401, `INGEST_SECRET` 미설정 시 503
- 같은 메시지 재전송 → 두 번 처리하지 않음
- 채널을 넘나드는 중복 → `중복 의심` 표시
- Redis 저장 경로 — Upstash REST를 흉내낸 로컬 서버로 실제 왕복 확인
- 담당자·우선순위 변경이 저장소에 반영되고 새로고침 후에도 유지
- 디스코드 채널 설정 파싱, 봇·빈 메시지 제외, 대화 합치기, 토큰 미설정 시 503

**디스코드와 Gmail 서버에 실제로 붙는 구간은 확인하지 못했다.** 작업 환경에서
두 서비스로의 외부 접속이 차단돼 있다. 봇 토큰과 채널 ID를 넣고 첫 수집이
도는지는 직접 확인해야 한다.

실제 Anthropic API 호출 경로는 Vercel 배포 환경에서 키를 넣고 확인했다.
데모 폴백이 걸리지 않고 모델 응답으로 카드가 그려진다.

아직 확인하지 않은 것: **추출 정확도.** 실제 인입 메일·대화로 측정한 적이 없다.
정확도를 주장하려면 진짜 원문 10~20건을 넣고 놓친 건수, 지어낸 건수,
직무 오분류 건수를 직접 세어야 한다.

## 자동 연동 설정

붙여넣기 없이 메일·디스코드에서 할일이 저절로 쌓이게 하려면 아래를 설정한다.
**아무것도 설정하지 않아도 앱은 그대로 동작한다** — 붙여넣기 흐름은 영향받지 않고,
화면 상단 `연동 상태`에 무엇이 꺼져 있는지 그대로 표시된다.

### 1. 저장소 (연동을 쓰려면 필수)

자동 수집은 아무도 화면을 보지 않을 때 들어오므로 담아둘 곳이 필요하다.
Upstash Redis를 붙이면 된다 (Vercel 마켓플레이스에 연동이 있다).

| 환경변수 | 비고 |
|---|---|
| `UPSTASH_REDIS_REST_URL` | Vercel 연동을 쓰면 `KV_REST_API_URL`로 들어온다. 둘 다 인식한다 |
| `UPSTASH_REDIS_REST_TOKEN` | 마찬가지로 `KV_REST_API_TOKEN`도 인식 |

설정하지 않으면 메모리로 강등된다. 서버리스에서는 인스턴스마다 따로 놀고 언제든
사라지므로 **실제로 유지되지 않는다.** 그래서 화면에 경고를 띄운다.

### 2. 메일 수신

Gmail OAuth 대신 **수신 웹훅** 방식이다. 인증 절차가 없다.

1. `INGEST_SECRET`에 아무 긴 문자열을 넣는다 (이게 없으면 수집 엔드포인트는 꺼진 채로 있다)
2. `POST https://<도메인>/api/ingest/email` 로 메일을 보내도록 설정하고,
   헤더 `x-ingest-secret: <INGEST_SECRET>`을 붙인다

보내는 쪽은 두 가지 방법이 있다.

**Gmail Apps Script (권장).** 도메인도 외부 서비스 가입도 필요 없다.
`docs/gmail-forwarder.gs`를 script.google.com에 붙여넣고 상단 세 값을 채운 뒤
시간 기반 트리거를 걸면 된다. Gmail에 `할일수집` 라벨을 만들고, 필터로 원하는
메일에 그 라벨이 붙게 하면 그 메일만 수집된다. 보낸 메일은 라벨을 떼므로
같은 메일을 다시 보내지 않고, 전송에 실패하면 라벨이 남아 다음 실행에서 재시도한다.

**메일 전달 서비스.** Cloudflare Email Routing, SendGrid Inbound Parse, Postmark 등.
도메인이 있으면 이쪽이 실시간에 가깝다. 서비스마다 필드 이름이 달라도 흡수한다.

JSON·form-urlencoded·multipart 세 형식을 모두 받고, 서비스마다 다른 필드 이름
(`subject`/`Subject`, `text`/`TextBody`/`body` 등)을 흡수한다.

**설정이 됐는지 확인하려면** 화면 상단 `연동 상태` 줄의 **메일 수신 테스트** 버튼을 누른다.
샘플 메일 한 통이 실제 수집 경로를 그대로 지나 대시보드에 나타난다.
메일 전달 서비스를 붙이기 전에 저장소·추출·저장·표시가 이어지는지 먼저 확인할 수 있다.
(버튼은 `INGEST_SECRET`이 설정돼 있을 때만 보이고, 분당 한 번으로 제한된다.)

명령줄에서 확인하려면:

```bash
curl -X POST https://<도메인>/api/ingest/email \
  -H "x-ingest-secret: <INGEST_SECRET>" \
  -H "Content-Type: application/json" \
  -d '{"subject":"테스트","text":"내일까지 보고서 정리해서 공유 부탁드립니다.","messageId":"t-1"}'
```

### 3. 디스코드 수집

| 환경변수 | 예시 |
|---|---|
| `DISCORD_BOT_TOKEN` | 개발자 포털에서 봇 생성 후 발급 |
| `DISCORD_CHANNELS` | `1234567890:#dev-일반, 9876543210:#cs-문의` |

봇 설정 시 **Message Content Intent를 켜야** 본문을 읽을 수 있다. 봇을 서버에 초대하고
해당 채널의 읽기 권한을 준다. 채널 ID는 디스코드에서 개발자 모드를 켜면 우클릭으로 복사된다.

**스레드도 함께 수집한다.** 채널을 설정하면 그 아래 스레드는 자동으로 따라온다.
따로 등록할 필요가 없다.

앰플랩 서버는 채널이 프로젝트·고객사 단위(`ai-os`, `판틀110`)라 실제 업무 대화가
그 아래 스레드(`[2026 현장실습] CRM 자동화 고객포탈`)에서 오간다.
채널 본문만 긁으면 그 대화가 통째로 누락된다 — 자동 수집을 붙이고도 남는 누락 지점이다.

- 활성 스레드는 서버 단위로 한 번에 받아 설정한 채널의 것만 고른다
- 보관된 스레드는 최근 7일 것만 본다. 오래 전 것까지 훑으면 첫 실행에서
  지나간 대화가 한꺼번에 할일로 올라온다
- 서버 id는 설정으로 받지 않고 채널 하나를 조회해 알아낸다
- 스레드를 못 읽어도(권한 없음 등) 채널 본문 수집은 계속되고, 이유가 화면에 남는다

읽은 위치를 채널·스레드별로 기억하므로 같은 메시지를 두 번 처리하지 않는다.
봇이 쓴 메시지와 빈 메시지는 건너뛴다. 흩어진 메시지는 대화 한 덩어리로 합쳐서
넘긴다 — 할일이 여러 발화에 걸쳐 있는 경우가 많아 한 건씩 넣으면 맥락이 끊긴다.

**지금 바로 수집하기.** 크론을 기다리지 않으려면 화면 상단 `연동 상태` 줄의
**디스코드 지금 수집** 버튼을 누른다. 채널별 결과(새 메시지 수, 추가된 할일 수,
또는 오류 메시지)가 그 자리에 표시된다. 공유 비밀을 주소창에 넣을 필요가 없다.
(`INGEST_SECRET`이 설정돼 있을 때만 보이고, 분당 한 번으로 제한된다.)

**수집 주기.** `vercel.json`의 크론은 하루 한 번으로 잡혀 있다. Vercel 무료 플랜은
크론 빈도에 제한이 있어 더 잦게 설정하면 배포가 거부될 수 있다 (플랜 정책은 바뀌므로
배포 후 Vercel의 Cron 화면에서 실제 적용 상태를 확인할 것). 더 자주 돌리려면:

- Pro 플랜이면 `vercel.json`의 `schedule`을 `*/10 * * * *` 등으로 바꾼다
- 무료 플랜이면 외부 크론 서비스에서
  `https://<도메인>/api/ingest/discord?secret=<INGEST_SECRET>` 을 주기적으로 호출한다

### 보안

수집 엔드포인트는 인터넷에 열려 있으므로 공유 비밀로 막는다.
`INGEST_SECRET`이 없으면 열어두지 않고 **거부한다** — 설정을 깜빡한 배포가
조용히 아무나 쓸 수 있는 상태로 열리는 것이 더 나쁘기 때문이다.
비밀 비교는 값에 따라 시간이 달라지지 않게 한다.

## 진단

배포 환경에서 데모 모드가 걸릴 때 원인을 확인하는 경로:

- 화면의 `데모 모드` 뱃지 옆에 폴백 사유가 그대로 표시된다.
- `/api/health` — 어떤 설정이 서버까지 도달했는지 항목별로. AI 키, 저장소
  (어느 이름으로 들어왔는지 포함), 메일 수신, 디스코드(토큰 유무와 채널 파싱 결과).
  값 자체는 반환하지 않는다.
- `/api/health?probe=1` — 실제로 한 번 호출해 AI 키 유효성까지 검사.

연동이 `미설정`으로 뜰 때는 이 주소부터 연다. 변수를 넣었는데 `false`로 나오면
재배포를 안 했거나 이름이 다르거나 Production에 적용되지 않은 것이다.

두 엔드포인트 모두 키 값 자체는 반환하지 않는다.

## 범위 밖

DB·인증·다중 사용자·실제 메일/디스코드 연동은 넣지 않았다. 상태는 새로고침하면 사라진다.
